Q: Using the Master Theorem, what is the solution to T(n) = 2T(n/2) + n?
Topic: Algorithms
- Θ(n)
* Θ(n log n)
- Θ(n²)
- Θ(n log² n)
Why: Here a = 2 and b = 2, so n^(log_b a) = n. The extra work f(n) = n matches that exactly, which is Master Theorem case 2, so you multiply by a log factor: Θ(n log n). This is merge sort's recurrence.

Q: Using the Master Theorem, what is the solution to T(n) = 8T(n/2) + n²?
Topic: Algorithms
- Θ(n² log n)
- Θ(n²)
* Θ(n³)
- Θ(n log n)
Why: a = 8 and b = 2, so n^(log₂ 8) = n³. The extra work n² grows polynomially slower than n³, so the recursion dominates (case 1) and T(n) = Θ(n³). This is naive divide-and-conquer matrix multiplication.

Q: What is the lower bound on the worst-case number of comparisons for any comparison-based sorting algorithm?
Topic: Algorithms
- Ω(n)
* Ω(n log n)
- Ω(n²)
- Ω(n log log n)
Why: Any comparison sort can be modeled as a binary decision tree with at least n! leaves, one per possible ordering. Its height is at least log₂(n!), which is Θ(n log n). Non-comparison sorts like counting sort or radix sort can beat this because they don't only compare elements.

Q: Which single-source shortest path algorithm works with negative edge weights, as long as there are no negative cycles?
Topic: Algorithms
- Dijkstra's algorithm
* Bellman-Ford
- Prim's algorithm
- Breadth-first search
Why: Bellman-Ford relaxes every edge V minus 1 times, which is enough for shortest paths with negative edges, in O(VE) time. One extra pass detects a negative cycle. Dijkstra can fail with negative edges because it finalizes a node as soon as it's popped.

Q: What is the time complexity of the Floyd-Warshall all-pairs shortest path algorithm?
Topic: Algorithms
- Θ(V²)
- Θ(V + E)
* Θ(V³)
- Θ(E log V)
Why: Floyd-Warshall is dynamic programming with three nested loops over the vertices. For each intermediate vertex k, it checks whether going through k shortens the path from i to j. That's V times V times V, so Θ(V³).

Q: For the activity-selection problem, which greedy choice always gives an optimal schedule?
Topic: Algorithms
- Pick the activity with the earliest start time
- Pick the shortest activity
* Pick the activity that finishes earliest
- Pick the activity with the fewest conflicts
Why: Choosing the earliest finishing activity leaves the most room for the rest. An exchange argument proves it: any optimal schedule can swap its first activity for the earliest finishing one without losing anything. The other rules have counterexamples.

Q: Why is the classic O(nW) dynamic programming solution to 0/1 knapsack called pseudo-polynomial?
Topic: Algorithms
- Because it only runs fast when n and W are both small, so on big inputs it falls back to brute force
* Because W is a number whose input size is only log W bits, so O(nW) is exponential in input length
- Because it relies on recursion, which makes the true running time hard to bound exactly
- Because it only approximates the best value, guaranteeing an answer within a constant factor
Why: Running time is measured against the input's length in bits. The capacity W takes about log W bits to write down, so a running time proportional to W is exponential in that length. That's why knapsack can be NP-complete yet still have this practical algorithm.

Q: What is the amortized cost of appending to a dynamic array that doubles its capacity when full?
Topic: Algorithms
* O(1)
- O(log n)
- O(n)
- O(n log n)
Why: An occasional resize copies n elements, but resizes get exponentially rarer. Over n appends the total copying is at most about 2n, so each append costs O(1) on average. The aggregate or potential method proves it.

Q: A directed graph has a topological ordering if and only if...
Topic: Algorithms
- it is strongly connected, so every vertex can reach every other one
* it has no directed cycles (it's a DAG)
- every vertex has in-degree at most 1
- it has no undirected cycles, so it's a tree or a forest
Why: In a cycle, every node would have to come before itself, which is impossible. Conversely, every DAG has a node with in-degree 0. Removing it repeatedly (Kahn's algorithm) or using DFS finishing times gives a valid order.

Q: What is the expected running time of randomized Quickselect for finding the k-th smallest element?
Topic: Algorithms
- O(log n)
* O(n)
- O(n log n)
- O(n²)
Why: Quickselect partitions like quicksort but only recurses into one side. With random pivots the expected sizes shrink geometrically: n + n/2 + n/4 and so on, which adds up to O(n). The worst case is still O(n²), and median-of-medians guarantees O(n) worst case.

Q: What is the time complexity of finding strongly connected components with Tarjan's or Kosaraju's algorithm?
Topic: Algorithms
- O(V²)
* O(V + E)
- O(VE)
- O(E log V)
Why: Both are built on depth-first search, which touches every vertex and edge a constant number of times. Kosaraju does two DFS passes, the second on the reversed graph. Tarjan does one pass using low-link values.

Q: What is the worst-case height of a red-black tree with n nodes?
Topic: Data Structures
- O(n), when keys are inserted in sorted order
* O(log n), at most 2·log₂(n + 1)
- O(√n), since rotations only fix half the imbalance
- Exactly ⌈log₂(n + 1)⌉, since red-black trees are perfectly balanced
Why: Every root-to-leaf path has the same number of black nodes, and red nodes can't be adjacent. So the longest path is at most twice the shortest, which keeps the height logarithmic. That guarantees O(log n) search, insert and delete.

Q: How long does it take to build a binary heap from an unsorted array of n elements using bottom-up heapify?
Topic: Data Structures
- O(n log n)
* O(n)
- O(log n)
- O(n²)
Why: Most nodes sit near the bottom and only sift down a short distance. Summing the heights over all nodes gives a series that converges to O(n). Inserting the elements one at a time would instead cost O(n log n).

Q: In a hash table using separate chaining with load factor α, what is the expected time for an unsuccessful search?
Topic: Data Structures
- Θ(1) always
* Θ(1 + α)
- Θ(log α)
- Θ(n)
Why: Under simple uniform hashing, the average chain length is α, the number of keys divided by the number of buckets. A miss hashes to a bucket (constant time) and scans the whole chain. Keeping α bounded by resizing keeps operations O(1) on average.

Q: Why are B-trees preferred over binary search trees for database and file-system indexes?
Topic: Data Structures
- They use less memory per key, since nodes store no child pointers
* Their high branching factor keeps the tree shallow, minimizing slow disk reads
- They never need rebalancing, so inserts are always constant time
- They store keys in hash buckets, which makes every lookup take one read
Why: Each B-tree node fills a disk page and holds many keys, so the height is roughly log base B of n. B can be in the hundreds, so a lookup touches only a few pages. Disk and SSD reads cost far more than in-memory comparisons.

Q: What is the amortized time for decrease-key in a Fibonacci heap?
Topic: Data Structures
* O(1)
- O(log n)
- O(n)
- O(log log n)
Why: Fibonacci heaps cut the node out and do cascading cuts lazily, which gives O(1) amortized decrease-key. That lets Dijkstra run in O(E + V log V), better than a binary heap's O(E log V) on dense graphs.

Q: What is the time to search for a key of length L in a trie?
Topic: Data Structures
- O(log n)
* O(L)
- O(n)
- O(L log n)
Why: A trie walks one character at a time from the root, so lookup depends on the key's length, not on how many keys are stored. That's why tries are good for prefix searches like autocomplete.

Q: What is the expected search time in a skip list with n elements?
Topic: Data Structures
- O(1)
* O(log n)
- O(√n)
- O(log log n)
Why: Each element is promoted to the next level with probability 1/2, giving about log n levels. A search drops down a level after about two steps forward per level. It matches balanced trees on average without any rotations.

Q: Which language is context-free but NOT regular?
Topic: Theory of Computation
- a*b*
* { aⁿbⁿ : n ≥ 0 }
- { aⁿbⁿcⁿ : n ≥ 0 }
- Strings with an even number of a's
Why: A finite automaton can't count without bound, which the pumping lemma for regular languages proves. A pushdown automaton can push the a's onto its stack and pop one for each b. aⁿbⁿcⁿ isn't even context-free, and the other two are regular.

Q: Which statement about the Halting Problem is true?
Topic: Theory of Computation
- It is decidable, but any algorithm that decides it takes exponential time
* It is undecidable, but it is recognizable (semi-decidable)
- It is neither recognizable nor co-recognizable
- It is co-recognizable, but not recognizable
Why: A universal Turing machine can run the program and accept if it halts, so the language is recognizable. Turing's diagonalization proof shows no machine can also always reject the ones that don't halt. Its complement is therefore not recognizable.

Q: What does the Cook-Levin theorem prove?
Topic: Theory of Computation
- P = NP, by giving a polynomial-time SAT algorithm
* Boolean satisfiability (SAT) is NP-complete
- The Halting Problem is undecidable
- 3-SAT can be solved in polynomial time with a stack
Why: Cook and Levin showed that any polynomial-time nondeterministic computation can be encoded as a Boolean formula that's satisfiable exactly when the machine accepts. That made SAT the first known NP-complete problem, and others are proved NP-complete by reducing from it.

Q: If problem A reduces to problem B in polynomial time (A ≤p B) and B is in P, what can you conclude?
Topic: Theory of Computation
- B is NP-hard
* A is in P
- A is NP-complete
- Nothing
Why: To solve A, translate the instance to B in polynomial time, then run B's polynomial algorithm. Polynomial plus polynomial is still polynomial. Reductions carry easiness downward and hardness upward.

Q: What does Rice's theorem state?
Topic: Theory of Computation
- Every property of a Turing machine's description, like its number of states, is undecidable
* Every nontrivial property of the language a Turing machine recognizes is undecidable
- Every nontrivial property of a context-free grammar is undecidable
- Every language property is decidable if the Turing machine always halts
Why: If a property is about what a program computes, not how it's written, and some programs have it while others don't, no algorithm can decide it for all programs. For example, "does this program ever print hello?" is undecidable.

Q: A tree with n vertices has how many edges?

Why: A tree is connected with no cycles. Start from one vertex and add the others one at a time, each with exactly one new edge: n - 1 edges. One more edge would create a cycle, and one fewer would disconnect it.

Q: Which of these is NOT one of the four necessary (Coffman) conditions for deadlock?
Topic: Operating Systems
- Mutual exclusion
- Hold and wait
* Preemption of resources
- Circular wait
Why: The four conditions are mutual exclusion, hold and wait, no preemption, and circular wait. If resources can be preempted, deadlock can be broken. Preventing deadlock means making at least one of the four impossible, for example by ordering locks to stop circular wait.

Q: Belady's anomaly, where adding page frames increases page faults, can happen with which replacement algorithm?
Topic: Operating Systems
* FIFO
- LRU
- Optimal (OPT)
- Any stack algorithm
Why: LRU and OPT are stack algorithms: the pages in memory with k frames are always a subset of those with k + 1 frames, so more frames never hurts. FIFO lacks that property, so more frames can occasionally cause more faults.

Q: What does the TLB (translation lookaside buffer) cache?
Topic: Operating Systems
- Recently used disk blocks, so files open faster
* Recent virtual-to-physical page translations
- Instructions that are about to be executed
- Recently used physical page frames and their contents
Why: Walking multi-level page tables costs several memory accesses. The TLB is a small, fast cache of recent page table entries, so most address translations skip the walk entirely.

Q: What is thrashing?
Topic: Operating Systems
- The CPU running so hot that it throttles its clock speed to cool down
* The system spends most of its time paging, because working sets don't fit in memory
- Two threads repeatedly taking and releasing the same lock without making progress
- A cache with so many conflict misses that it's slower than having no cache
Why: When memory is overcommitted, every process keeps faulting on pages another process just evicted. CPU utilization collapses while the disk stays busy. Fixes include reducing multiprogramming or giving processes enough frames for their working sets.

Q: Why is a context switch between two threads of the same process cheaper than between two processes?
Topic: Operating Systems
- Threads don't have their own registers, so there's nothing to save or restore
* Threads share an address space, so page tables and TLB contents don't have to change
- Threads can't be preempted, so switches only happen when a thread chooses to yield
- The kernel isn't involved, since threads are always scheduled in user space
Why: Switching processes means switching address spaces: a new page table base and often a TLB flush, plus colder caches. Threads in one process share memory, so only registers and the stack pointer change.

Q: What is the classic fix for priority inversion?
Topic: Operating Systems
- Round-robin scheduling
* Priority inheritance
- Increasing the time quantum
- Disabling interrupts permanently
Why: With priority inheritance, a low-priority task holding a lock temporarily takes the priority of the highest task waiting for it. Medium-priority tasks can't preempt it, so it finishes and releases the lock quickly. This famously fixed the Mars Pathfinder resets.

Q: How does copy-on-write make fork() efficient?
Topic: Operating Systems
- It skips creating a new process and runs the child as a thread of the parent
* Parent and child share pages read-only, and a page is copied only when one writes to it
- It copies the parent's memory to disk, then loads it lazily into the child
- It shares only the file descriptors, and the child starts with empty memory
Why: Many children call exec() right after fork(), so copying the whole address space would be wasted. With copy-on-write, both share the physical pages until a write causes a fault, and only then does the kernel copy that one page.

Q: If 90% of a program can be parallelized, what is the maximum speedup with unlimited processors, according to Amdahl's law?
Topic: Computer Architecture
- 90x
* 10x
- Unlimited
- 9x
Why: Speedup = 1 / ((1 - p) + p/N). As N goes to infinity, the parallel part vanishes and you're left with 1 / 0.1 = 10. The serial 10% caps the speedup no matter how many cores you add.

Q: In a pipelined processor, what technique resolves most read-after-write data hazards without stalling?
Topic: Computer Architecture
- Branch prediction
* Forwarding (bypassing)
- Increasing the clock rate
- Adding more cache
Why: Forwarding sends a result straight from a later pipeline stage back to an earlier one that needs it, instead of waiting for it to be written to the register file. Some hazards, like a value used right after a load, still need a one-cycle stall.

Q: In a write-back cache, when is modified data written to main memory?
Topic: Computer Architecture
- On every store, in the same cycle as the cache update
* When the dirty block is evicted
- Every time the CPU reads the block
- Only when the program terminates
Why: Write-back marks a block as dirty when it's modified and only writes it to memory when it's evicted. That saves memory bandwidth compared to write-through, which writes to memory on every store, at the cost of extra complexity for coherence.

Q: Increasing a cache's associativity mainly reduces which kind of miss?
Topic: Computer Architecture
- Compulsory misses
- Capacity misses
* Conflict misses
- Coherence misses
Why: Conflict misses happen when blocks that map to the same set evict each other even though the cache has room elsewhere. More ways per set gives those blocks more places to go. Compulsory misses come from the first access, and capacity misses come from the cache simply being too small.

Why: Each ACK grows the window by one segment, so the window roughly doubles each round trip until it hits the slow-start threshold or a loss. After that, congestion avoidance grows it linearly (additive increase, multiplicative decrease).

Q: What does strict two-phase locking (2PL) guarantee?

Q: What is write-ahead logging (WAL) for?

Q: What compiler analysis is used to decide which variables can share a register?

Q: What does tail-call optimization do?
Topic: Compilers & Languages

Why: If a call is the very last thing a function does, its frame isn't needed anymore, so the call can become a jump. Tail-recursive loops then run in O(1) stack space instead of overflowing.

- Finding collisions in SHA-256
- Solving the elliptic curve discrete log
Why: The public key includes n = p·q. Computing the private exponent requires φ(n) = (p - 1)(q - 1), which effectively requires factoring n. Diffie-Hellman and elliptic-curve crypto rely on discrete logarithms instead.

Q: What attack is unauthenticated Diffie-Hellman key exchange vulnerable to?
Topic: Security
- Brute force of the shared key
* Man-in-the-middle
- SQL injection
- Rainbow tables
Why: Without authentication, an attacker can run separate key exchanges with each side and relay traffic, reading everything. TLS stops this by having the server sign its key share with a certificate-backed key.

Q: What does salting password hashes defend against?
Topic: Security
- Weak passwords being guessed one at a time by attackers trying common words
* Precomputed rainbow tables, and identical passwords having identical hashes
- Keyloggers recording passwords as users type them in
- Passwords being stolen in transit before they reach the server
Why: A unique random salt per user means attackers can't reuse a precomputed table and have to attack each hash separately. To slow down per-password guessing too, you also need a deliberately slow hash like bcrypt, scrypt or Argon2.

Q: What is the standard defense against cross-site request forgery (CSRF)?
Topic: Security
- Escaping all HTML output so injected scripts can't run
* Anti-CSRF tokens and SameSite cookies
- Serving every page over HTTPS only
- Limiting the length of form inputs
Why: In CSRF, another site makes the victim's browser send a request that carries their cookies. A secret per-session token that the attacker's page can't read, plus SameSite cookies, stops it. Escaping output is the fix for XSS, a different attack.

Q: Which of these mitigates stack buffer overflow exploits?
Topic: Security
- Longer passwords and account lockouts
* Stack canaries, ASLR, and non-executable stacks (DEP/NX)
- Firewalls that block unusual ports
- Salting and hashing every stored string
Why: A canary detects an overwritten return address before the function returns. ASLR randomizes where code lives, so jump targets are hard to guess. NX stops injected data from running as code. Attackers respond with techniques like return-oriented programming.

Q: How does a digital signature work?
Topic: Security
- Encrypt the message with the recipient's public key, so only the recipient can read it
* Sign a hash of the message with the sender's private key; anyone verifies with the public key
- Sign the message with the sender's public key; the receiver verifies with their private key
- Append a shared secret key to the message, so the receiver knows who sent it
Why: Only the private key holder can produce the signature, so it proves who sent the message, and any change to the message breaks verification. It provides authenticity and integrity, not confidentiality.

Q: What does the Liskov Substitution Principle require?
Topic: Software Engineering
- Every class should have only one reason to change
* Subtype objects must work anywhere the base type is expected, without breaking correctness
- Depend on abstractions, not on concrete classes
- Classes should be open for extension but closed for modification by other code
Why: A subclass has to honor the base class's contract: no stronger preconditions, no weaker postconditions. The classic violation is a Square inheriting from Rectangle, where setting the width secretly changes the height.

Q: Which HTTP method is NOT idempotent?
Topic: Software Engineering
- GET
- PUT
- DELETE
* POST
Why: Idempotent means doing it many times has the same effect as doing it once. PUT replaces a resource and DELETE removes it, so repeating them changes nothing more. POST typically creates a new resource each time.

Q: What is dependency injection?
Topic: Software Engineering
- Importing every library globally so any class can use any dependency
* Giving an object its dependencies from outside instead of having it create them
- An attack that inserts malicious code into a project's dependencies
- Bundling all of a program's dependencies into a single file
Why: Passing collaborators in through the constructor or parameters decouples classes, which makes them easy to swap for mocks in tests. It's one way to apply the Dependency Inversion Principle.

Q: Which design pattern lets objects subscribe to be notified when another object's state changes?
Topic: Software Engineering
- Singleton
- Factory
* Observer
- Adapter
Why: In Observer, a subject keeps a list of subscribers and notifies them of changes. It's the basis of event listeners and of reactive UI frameworks.

Q: What is the purpose of regression testing?
Topic: Software Engineering
- Testing how the system performs under heavy load
* Re-running existing tests to make sure changes didn't break things that used to work
- Testing with real users to see how they use the product
- Testing only the newest features before each release goes out
Why: Each change risks breaking old behavior. An automated regression suite, usually run in CI on every commit, catches those breaks early, before they reach users.

Q: Must-know: what are the three cases of the Master Theorem for T(n) = aT(n/b) + f(n)?
Topic: Must-Know Facts
* Compare f(n) with n^(log_b a): smaller gives Θ(n^(log_b a)), equal gives Θ(n^(log_b a) log n), larger gives Θ(f(n))
- Compare a with b: a < b gives Θ(n), a = b gives Θ(n log n), a > b gives Θ(n²)
- Compare f(n) with n: smaller gives Θ(log n), equal gives Θ(n), larger gives Θ(n log n)
- Compare a with f(n): smaller gives Θ(a), equal gives Θ(a log n), larger gives Θ(f(n) log n)
Why: n^(log_b a) is the total work at the leaves of the recursion tree. Whichever side dominates, the leaves or the top-level work f(n), sets the answer. Merge sort (a = 2, b = 2, f = n) is the "equal" case.

Q: Must-know: what is Amdahl's law for the speedup when a fraction p of a program is sped up by a factor s?
Topic: Must-Know Facts
* Speedup = 1 / ((1 − p) + p/s)
- Speedup = 1 / (p + (1 − p)/s)
- Speedup = p · s
- Speedup = (1 − p) + p · s
Why: The part you can't speed up limits the whole program. Even with infinite cores, a program that's 10% serial can't run more than 10 times faster.

Q: Must-know: what is the effective memory access time with a cache?
Topic: Must-Know Facts
* hit time + miss rate × miss penalty
- hit rate × miss penalty + hit time
- miss rate × hit time + miss penalty
- (hit time + miss penalty) / 2
Why: Every access pays the hit time, and misses also pay the penalty for going to the next level. With a 1 ns hit time, a 5% miss rate and a 100 ns penalty, the average is 1 + 0.05 × 100 = 6 ns.

Q: Must-know: how many usable host addresses are in a /24 IPv4 subnet?

Why: A /24 leaves 8 bits for hosts, giving 2⁸ = 256 addresses. The all-zeros network address and the all-ones broadcast address can't be assigned, which leaves 254.

Q: Must-know: what is the main condition for a relation to be in BCNF?

- Every non-key attribute depends on the whole key
- No non-key attribute depends on another non-key attribute
- Every attribute holds a single atomic value
Why: These go up in strictness: atomic values (1NF), no partial dependencies (2NF), no transitive dependencies (3NF), then every determinant is a superkey (BCNF).

- Mutual exclusion, progress, bounded waiting, no preemption

Q: Must-know: what is the time complexity of Dijkstra's algorithm with a binary heap?

- O(V · E)
- O(V³)
- O(V + E)
Why: Each vertex is removed from the heap once and each edge may cause a decrease-key, and each heap operation costs O(log V). Bellman-Ford is O(V·E) and Floyd-Warshall is O(V³).

Q: Must-know: what does the CAP theorem say a distributed system can't fully guarantee all at once?
