Q: Which data structure follows Last-In, First-Out (LIFO) order?
Topic: Data Structures
- Queue
* Stack
- Linked list
- Heap
Why: A stack is LIFO: the last item pushed is the first one popped, like a stack of plates. A queue is the opposite (FIFO).

Q: What is the average time complexity to look up a key in a hash table?
Topic: Data Structures
* O(1)
- O(log n)
- O(n)
- O(n log n)
Why: A hash function maps the key straight to a bucket, so lookup is O(1) on average. Worst case (many collisions) degrades to O(n).

Q: In a binary search tree, where are values smaller than a node stored?
Topic: Data Structures
- In its right subtree
* In its left subtree
- In its parent
- Anywhere in the tree
Why: The BST property: everything in the left subtree is smaller than the node and everything in the right subtree is larger. That ordering is what makes searching fast.

Q: What is the time complexity of accessing the element at index i in an array?
Topic: Data Structures
- O(n)
- O(log n)
* O(1)
- O(i²)
Why: Arrays are stored contiguously, so the address of element i is just base + i × element_size. That's a single calculation: O(1).

Q: Which data structure is typically used to implement a priority queue?
Topic: Data Structures
- Stack
* Heap
- Hash table
- Doubly linked list
Why: A binary heap keeps the highest (or lowest) priority element at the root, giving O(1) peek and O(log n) insert/remove.

- A value and pointers to the next and previous nodes
* A value and a pointer to the next node
- Only a value
- A key and a hash
Why: A singly linked list node holds data and one pointer to the next node. A doubly linked list adds a pointer to the previous node too.

Q: What is the worst-case time complexity of binary search on a sorted array?
Topic: Algorithms
- O(n)
* O(log n)
- O(1)
- O(n log n)
Why: Binary search halves the search space each step, so it takes about log₂(n) steps. 1,000,000 items need only ~20 comparisons.

Q: What is the average time complexity of merge sort?
Topic: Algorithms
- O(n²)
- O(n)
* O(n log n)
- O(n² log n)
Why: Merge sort splits the list in half log n times, and merging at each level costs O(n), giving O(n log n) in every case.

Q: What is the worst-case time complexity of quicksort?
Topic: Algorithms
- O(n log n)
* O(n²)
- O(n)
- O(log n)
Why: If the pivot is always the smallest or largest element (e.g. already-sorted input with a naive pivot), each partition only removes one element, giving O(n²). Its average case is O(n log n).

Q: Which algorithm finds the shortest path from one node to all others in a graph with non-negative edge weights?
Topic: Algorithms
- Breadth-first search
* Dijkstra's algorithm
- Kruskal's algorithm
- Bellman-Ford with negative cycles
Why: Dijkstra's algorithm repeatedly picks the closest unvisited node and relaxes its edges. It requires non-negative weights; Bellman-Ford handles negative ones. Kruskal's builds a minimum spanning tree, not shortest paths.

Q: Breadth-first search (BFS) uses which data structure to track nodes to visit?
Topic: Algorithms
- Stack
* Queue
- Heap
- Hash table
Why: BFS visits nodes level by level, so it uses a FIFO queue. Depth-first search (DFS) uses a stack (or recursion).

Q: What technique solves problems by storing results of overlapping subproblems to avoid recomputing them?
Topic: Algorithms
- Greedy algorithms
- Divide and conquer
* Dynamic programming
- Backtracking with pruning
Why: Dynamic programming caches subproblem answers (memoization or tabulation). Computing Fibonacci with DP is O(n) instead of exponential.

Q: What does Big-O notation describe?
Topic: Algorithms
- The exact runtime of an algorithm in seconds on a typical computer
* An upper bound on how runtime or memory grows with input size
- The best-case performance, when the input is already in the ideal order
- The average number of lines of code each step of the algorithm needs
Why: Big-O describes the growth rate (an upper bound) of time or space as n grows, ignoring constants. It's about scaling, not exact seconds.

Q: What is a recursive function's 'base case'?
Topic: Algorithms
- The first recursive call the function makes
* The condition that stops the recursion
- The call that does the most work
- The case where the input is the largest
Why: The base case is the condition where the function returns without calling itself. Without it, recursion never ends and you get a stack overflow.

Q: What is the time complexity of bubble sort in the worst case?
Topic: Algorithms
- O(n)
- O(n log n)
* O(n²)
- O(2ⁿ)
Why: Bubble sort compares adjacent pairs and makes up to n passes over n elements: n × n = O(n²).

Q: What is a 'race condition'?

Q: What is the difference between a process and a thread?

Why: A process is a running program with its own isolated memory. Threads are lighter-weight units of execution inside a process that share its memory, which makes communication easy but needs synchronization.

Q: What is 'virtual memory'?

- A special kind of RAM that's faster than normal memory because it's closer to the CPU
- Memory that is reserved only for virtual machines running on the computer
Why: Virtual memory maps each process's addresses to physical RAM through page tables, and can swap rarely used pages to disk. This isolates processes and lets programs use more memory than physically exists.

Q: What is a 'deadlock'?
Topic: Operating Systems
- When the CPU gets too hot and slows down to protect itself
* When processes each wait for a resource another holds, so none can proceed
- When one process uses so much CPU that other processes never get a turn
- When a program's memory fills up and it can't allocate more
Why: Example: thread A holds lock 1 and wants lock 2, while thread B holds lock 2 and wants lock 1. Both wait forever.

Q: What is the 'kernel' of an operating system?

Q: What does a CPU scheduler do?

* Decides which process or thread runs on the CPU next
- Decides when the computer should install updates
- Decides which program files to keep in the cache
Why: The scheduler switches between runnable tasks (context switching) so many programs appear to run at once, using policies like round-robin or priority scheduling.

Q: What is a 'page fault'?

- A corrupted area of the disk that can't be read
Why: When a process touches a virtual page not currently in physical memory, the CPU raises a page fault and the OS loads the page (often from disk). It's normal, not necessarily an error.

Q: Why should passwords be stored as hashes rather than plain text?

* So if the database leaks, attackers don't get the actual passwords

- So passwords can be compared faster when users log in
Why: A hash is one-way, so the site can verify a password without storing it. Use slow, salted algorithms like bcrypt or Argon2 so leaked hashes are hard to crack.

Q: What does it mean if a problem is 'NP-complete'?

Q: What is the Halting Problem?

Why: Alan Turing proved in 1936 that no general algorithm can determine whether every possible program halts. It's a foundational result about the limits of computation.

Q: Must-know: order these from fastest to slowest growth for large n.
Topic: Must-Know Facts
* O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ)
- O(1), O(n), O(log n), O(n log n), O(2ⁿ), O(n²)
- O(log n), O(1), O(n), O(n²), O(n log n), O(2ⁿ)
- O(1), O(log n), O(n log n), O(n), O(n²), O(2ⁿ)
Why: Memorize this ladder; it's on almost every CS exam. For n = 1,000,000: log n is about 20, n log n about 20 million, and n² is a trillion.

Q: Must-know: what is the time complexity of binary search on a sorted array?
Topic: Must-Know Facts
* O(log n)
- O(n)
- O(1)
- O(n log n)
Why: Each step throws away half of what's left, so 1,000,000 items need only about 20 comparisons. It only works on sorted data with direct index access.

Q: Must-know: what is the average time to look up a key in a hash table?
Topic: Must-Know Facts
* O(1)
- O(log n)
- O(n)
- O(n log n)
Why: The hash function jumps straight to the right bucket. The worst case is O(n) if many keys collide, which a good hash function and resizing make rare.

Q: Must-know: what is the time complexity of BFS or DFS on a graph with V vertices and E edges, using adjacency lists?
Topic: Must-Know Facts
* O(V + E)
- O(V · E)
- O(V²)
- O(E log V)
Why: Each vertex is visited once and each edge is looked at once (twice for undirected graphs). With an adjacency matrix it becomes O(V²).

Q: Must-know: which sorting algorithms run in O(n log n) in the worst case?
Topic: Must-Know Facts
* Merge sort and heapsort
- Quicksort and insertion sort
- Bubble sort and selection sort
- Quicksort and merge sort
Why: Quicksort is O(n log n) on average but O(n²) in its worst case. Bubble, selection and insertion sort are all O(n²), though insertion sort is fast on nearly sorted data.

Q: Must-know: what is the binary (base 2) value of decimal 13?
Topic: Must-Know Facts
* 1101
- 1011
- 1110
- 1001
Why: 13 = 8 + 4 + 1, so the 8s, 4s and 1s places are on: 1101. Repeatedly dividing by 2 and reading the remainders from the bottom up gives the same answer.

Q: Must-know: in 8-bit two's complement, what range of integers can be stored?
Topic: Must-Know Facts
* −128 to 127
- −127 to 127
- 0 to 255
- −256 to 255
Why: With n bits, two's complement covers −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1. There's one more negative number than positive because zero takes one of the non-negative patterns.

Q: Must-know: what are the 4 pillars of object-oriented programming?
Topic: Must-Know Facts
* Encapsulation, abstraction, inheritance, polymorphism
- Classes, objects, methods, variables
- Encapsulation, compilation, inheritance, recursion
- Abstraction, iteration, recursion, polymorphism
